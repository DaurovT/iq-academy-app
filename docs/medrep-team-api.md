# Команда медпреда и кодовое слово — контракт API

Сервер (platform_api) готов, экраны рисуются по макетам MedInvite / MedPharmacists («Команда») /
MedPending / RegDoctorCode. Базовый адрес: `https://pharmview.uz/api/1.0`.

## Кодовое слово

Код — 6 символов из ника медпреда (латиница, верхний регистр; при совпадении хвост заменяется
цифрами). Регистр при вводе не важен, лишние символы отбрасываются.

### `GET /client/medrep/code` (медпред)

```json
{
  "code": "PANIKA",
  "username": "pani_kalinina",
  "company": "Bionorica SE",
  "joinedByCode": 12,
  "inviteLink": "https://t.me/PharmQuestBot?start=ref_1906911721"
}
```

## Регистрация

Анкета приходит с сервера (`GET /reference/registration-schema?role=doctor|pharmacist`) — поле
`medrepCode` уже там: у врача `required: true`, у фармацевта `false`, `maxLength: 6`, есть `hint`.

### `POST /auth/medrep-code/check` — проверка кода на экране регистрации

Запрос `{"code": "panika"}` → `{"ok": true, "medrep": {"name": "Вольга Калинин", "company": "Bionorica SE"}}`
или `{"ok": false}` (показать ошибку «Такого кодового слова нет…»).

### `POST /auth/register`

В `values` добавляется `medrepCode`. Правила:

| Роль | Код | Что будет |
|---|---|---|
| Врач | обязателен | без кода 400 «Укажите код медпреда…», с неверным — 400 «Неверный код медпреда»; с верным — **сразу в команду** |
| Фармацевт | по желанию | с верным кодом — в **«Ожидают подтверждения»** у медпреда; неверный код — 400 |

### `POST /client/account/medrep-code` — ввести код позже (из профиля)

`{"code": "PANIKA"}` → `{"ok": true, "medrep": {...}}`. Правила те же: врач попадает в команду,
фармацевт — в ожидающие.

## Экран «Команда»

### `GET /client/medrep/team`

```json
{
  "totals": {"all": 23, "doctors": 6, "pharmacists": 17, "pending": 3},
  "doctors": [{
    "accountId": 2879, "telegramId": 1906911721, "role": "doctor",
    "name": "Нодира Юсупова", "specialty": "Терапевт", "workplace": "Поликлиника №10",
    "city": "Ташкент", "phone": "+998901234567",
    "recipes": 34, "approved": 30, "lastAt": "2026-10-07T08:00:00+00:00",
    "active": true, "joinedAt": "2026-10-01T10:00:00+00:00"
  }],
  "pharmacists": [{
    "telegramId": 123456, "accountId": null, "role": "pharmacist",
    "name": "Зиёда Азизова", "shop": "MARXAMAT MED FARM №4", "city": "Ташкент",
    "checks": 89, "quests": 2, "lastAt": "2026-10-06T12:00:00+00:00", "active": true
  }]
}
```

- Вкладки «Все / Фармацевты / Врачи» — из `totals`.
- Бейдж «Активный / Пассивный» — поле `active` (действие за последние 30 дней).
- Показатель в строке: у фармацевта `checks` («чеков»), у врача `recipes` («рецептов»).
- Поиск по имени, аптеке, клинике и городу — на клиенте, список приходит целиком (до 300 на роль).
- Фармацевты приходят и из бота (ссылка-приглашение), и из приложения (по коду, после подтверждения).

## Экран «Ожидают подтверждения»

### `GET /client/medrep/referrals/pending`

```json
[{"id": 2881, "kind": "app", "name": "Шахноза Нурматова", "phone": "+99890…",
  "shop": "SHIFO PLUS №3", "source": "code", "requestedAt": "2026-10-08T06:00:00+00:00"}]
```

- `source`: `code` → «Ввёл кодовое слово», `link` → «Перешёл по ссылке».
- `kind`: `app` — заявка из приложения, `bot` — из бота по ссылке.

### Принять / отклонить

| Откуда заявка | Принять | Отклонить |
|---|---|---|
| `kind: "app"` | `POST /client/medrep/team/pending/{id}/accept` | `POST /client/medrep/team/pending/{id}/reject` |
| `kind: "bot"` | `POST /client/medrep/referrals/{id}/accept` | `POST /client/medrep/referrals/{id}/reject` |

## Что ещё учесть

- Ссылка-приглашение остаётся в формате бота (`?start=ref_<telegram_id>`): бот не трогаем, кодовое
  слово работает только в приложении. На макете MedInvite подпись «кодовое слово уже внутри ссылки»
  стоит заменить на «ссылка для фармацевтов — через бота».
- В боте «Врачебный Практикум» кодовое слово не спрашивается — врачей там раскидывают вручную.
- Медпреду приходит уведомление в приложение: врач — «присоединился к вашей команде по коду»,
  фармацевт — «ввёл ваш код и ждёт подтверждения».
