## Задача 1. Заявки по кодовому слову из приложения — видны в админке — готово

**Проблема.** Фармацевт, который ввёл кодовое слово медпреда в приложении (при регистрации или
из профиля — `POST /client/account/medrep-code`), попадает в «Ожидают подтверждения» у медпреда
(`GET /client/medrep/referrals/pending`, элементы с `kind: "app"`). В админке таких заявок не
видно нигде: `GET /admin/medreps/{mid}/pending` и `pendingCount` показывают только заявки из
бота (`pharm_ref_pending`). Поддержка не может проверить и принять заявку. Случай 19.11.2026:
медпред Мафтуна Бахрамова (medrep id 144, Bionorica SE, код BNO535) не видела двух фармацевтов;
их привязали вручную `POST /admin/users/{tid}/medreps`.

**Сделать:**

1. `GET /admin/medreps/{mid}/pending` — отдавать и заявки из приложения. У каждой записи:
   `id`, `kind: "app" | "bot"`, `source: "code" | "link"`, `name`, `phone`, `shop`, `city`,
   `requestedAt`. Для `kind: "app"` — ещё `accountId`.
2. `pendingCount` в `/admin/medreps`, `/admin/medreps/{mid}` и `pending` / `pendingMedreps` в
   `/admin/medreps-summary` — считать оба вида заявок.
3. Принять / отклонить заявку из приложения из админки. Либо расширить существующие
   `POST /admin/medreps/{mid}/pending/accept|reject` (параметр `kind`), либо отдельные
   эндпоинты. Логика — та же, что у `POST /client/medrep/team/pending/{id}/accept|reject`
   (фармацевт попадает в команду, уведомления те же).
4. В карточке пользователя-фармацевта (`GET /admin/users/{tid}` или карточке аккаунта
   приложения) — поле с ожидающей заявкой: к какому медпреду и с какого времени.
5. Если админка — отдельный фронтенд, показать заявки из приложения на экране медпреда
   («Ожидают подтверждения») с пометкой «из приложения».

**Проверка:** создать тестовую заявку из приложения (демо-фармацевт `+998 90 111 22 33`, код
00000, Профиль → «Кодовое слово медпреда»), убедиться, что она видна в
`/admin/medreps/{mid}/pending`, принимается из админки и после этого фармацевт есть в
`GET /client/medrep/team` медпреда.

## Задача 2. Бланки врачей в статистике медпреда — готово

**Проблема.** `GET /client/medrep/metrics` считает только чеки фармацевтов. У медпредов, в
команде которых врачи (Bionorica SE), все показатели — 0, хотя врачи отправляют сотни бланков.

**Сделать:** добавить в ответ `GET /client/medrep/metrics` (с теми же `from` / `to`) три поля:

```json
{
  "mode": "shared", "pharmCount": 17, "checksCount": 206, "approvedPacksSum": 266, "questsDone": 2,
  "recipesCount": 73,
  "approvedRecipes": 63,
  "recipePacksSum": 118
}
```

- `recipesCount` — бланки врачей команды медпреда за период, кроме отклонённых.
- `approvedRecipes` — из них одобренные.
- `recipePacksSum` — упаковки из одобренных бланков, только препараты компании медпреда.
- Врачи команды — те же, что в `doctors` из `GET /client/medrep/team`. Атрибуция (`mode`) — как
  у фармацевтов.
- `questsDone` — плюс закрытые рецептурные квесты врачей команды.
- Отдавать поля **всегда** (нули, если врачей нет): по наличию `recipesCount` приложение
  понимает, что сервер умеет считать бланки, и показывает плитку «Бланки».

## Задача 3. Рейтинг медпредов по бланкам и по врачам — готово

`GET /client/medrep/leaderboard?metric=...` сейчас знает `checks | pharm | quests`. Добавить:

- `metric=recipes` — одобренные бланки врачей команды;
- `metric=doctors` — сколько врачей в команде (аналог `pharm`).

Формат ответа прежний (`mode`, `metric` = запрошенное значение, `items[].rank/name/value/isMe`,
`myRank`, `company`). Сравниваются медпреды одной компании.

## Задача 4. Пересчёт показателей чаще раза в сутки — готово

Сейчас показатели медпредов (для `metrics`, `leaderboard`, `/admin/medreps`) пересчитываются раз
в сутки — `metricsAt` около 03:03 UTC (08:03 Ташкент). Днём рейтинг не меняется. Пересчитывать
хотя бы раз в 15–30 минут или считать на лету.

## Задача 5 (по желанию). Админка — готово

В `/admin/medreps` и `/admin/medreps/{mid}` — `doctorsCount`, `recipesCount`, `approvedRecipes`,

# 24.11.2026 — врачи медпредов: привязка в админке и загрузка списка

> **Статус: не начато.**

**Жалоба.** Медпреды Bionorica: «статистика по МП в приложении некорректная, не учитывается
статистика по врачам». В рейтинге 35 медпредов Bionorica у большинства 0.

**Причина.** Врач попадает в статистику медпреда (`metrics.recipesCount`, `leaderboard?metric=
recipes|doctors`, `team.doctors`) только если сам ввёл кодовое слово медпреда. Почти все врачи
(в системе 548, из них 232 с бланками) пришли через бота «Врачебный Практикум» без слова и ни к
кому не привязаны. На 24.11 врачи в команде есть только у 7 медпредов из 35 (Мафтуна Бахрамова —
9, Саодат Бионорика — 7, Абдулазиз Риксиев — 5, ШГБ — 4, ещё трое по 1–2). В админке связи
«врач → медпред» нет совсем: ни поля в `GET /admin/doctors/{tid}`, ни эндпоинта.

**Решение владельца (24.11.2026):** привязка врача к медпреду в админке (как у фармацевтов).
Врачей по медпредам команда раскидает **вручную в админке** — загрузка списка не нужна
(задача 7 отменена). Поэтому в админке важны удобство и скорость ручной привязки: фильтр
«без медпреда», поиск по ФИО / телефону / городу, выбор медпреда прямо из списка врачей.

## Задача 6. Привязка врача к медпреду

1. Хранить связь врач ↔ медпред (одна на компанию, как у фармацевтов: выбор медпреда той же
   компании заменяет прежнего). Источник связи: `code` (кодовое слово), `admin` (вручную),
   `import` (из списка). Врач по кодовому слову — как сейчас, сразу в команде.
2. `POST /admin/doctors/{tid}/medreps` `{medrepId}` — привязать / сменить; `DELETE
   /admin/doctors/{tid}/medreps/{mid}` — отвязать. Работает и для врачей бота (только
   `telegramId`), и для врачей приложения (`accountId`).
3. `GET /admin/doctors/{tid}` и список `GET /admin/doctors` — поле `medreps: [{id, name,
   company, source, linkedAt}]`; в списке — фильтр «без медпреда».
4. В `platform_admin` (владелец будет раскидывать ~500 врачей **вручную** — это главный экран
   задачи):
   - **карточка врача** — блок «Медпред»: текущий медпред (или «не привязан») и кнопка
     «Привязать / Сменить» с выбором медпреда (поиск по имени, группировка по компании);
     «Отвязать»;
   - **список врачей** — колонка «Медпред», фильтры «без медпреда» и «медпред: …», поиск по
     ФИО / телефону / городу / месту работы; **массовая привязка**: отметить несколько врачей
     галочками → «Привязать к медпреду…» → выбор медпреда → подтверждение;
   - **карточка медпреда** — список его врачей (ФИО, город, бланков / одобрено) с «Отвязать» и
     кнопкой «Добавить врачей» (тот же выбор из списка «без медпреда»);
   - все действия пишутся в журнал админки (кто, когда, какого врача к кому).
6. `POST /admin/doctors/medreps-bulk` `{medrepId, doctors: [{telegramId?|accountId?}]}` — для
   массовой привязки; ответ — сколько привязано, сколько переведено от другого медпреда.
5. Все врачи, привязанные любым способом, считаются врачами команды медпреда везде:
   `GET /client/medrep/team` (`doctors`), `GET /client/medrep/doctors/{accountId}` (карточка
   врача у медпреда — должна открываться и для врача бота: если `accountId` нет, принимать
   `telegramId`), `metrics` (`recipesCount`, `approvedRecipes`, `recipePacksSum`,
   `doctorsCount`), `leaderboard?metric=recipes|doctors`, `/admin/medreps*`.

## Задача 7. Загрузка списка «медпред → врачи» — отменена (24.11.2026, врачей раскидают вручную)

3. Отчёт импорта — в ответе и скачиваемым xlsx.

## Задача 8. Рейтинг: общие места и имя в своей строке

`GET /client/medrep/leaderboard`:

1. **Места при равенстве — общие** («1, 2, 2, 4»): сейчас нумерация подряд, и при всех нулях
   медпред видит «35 место из 35, до 34 места ещё 0 чеков». `myRank` — по тому же правилу.
2. **В своей строке (`isMe: true`) — настоящее имя медпреда**, а не «Вы»: приложение само
   рисует «Вы · {имя}», получалось «Siz · Вы» / «Вы · Вы».

Приложение с версии после 1.2.5 само пересчитывает места при равенстве и подставляет имя из
аккаунта, если пришло «Вы», — но старые версии этого не делают.

## Как проверить

- Привязать в админке врача бота (например, telegramId 676570560 — 161 одобренный бланк) к
  медпреду Bionorica → у медпреда растут `doctorsCount`, `recipesCount`, он в
  `team.doctors`, карточка врача открывается из приложения медпреда.
- Рейтинг: у медпредов с одинаковым значением одинаковый `rank`; `isMe`-строка с именем.

# 24.11.2026 — версии приложения: подсказка «Доступна новая версия» и обязательное обновление

> **Статус: не начато.** Приложение готово с версии 1.2.6.

## Задача 9. Версии приложения в `GET /client/app-config` и в админке

Сейчас пользователи не узнают о новой версии, пока магазин не обновит приложение сам. С 1.2.6
приложение читает версии из `GET /client/app-config` (тот же ответ, где `modules`) и:

- если установленная версия **ниже `latest`** — показывает над нижним меню плашку
  «Доступна новая версия X · Обновить» (кнопка ведёт в App Store / Google Play, плашку можно
  закрыть до следующего запуска);
- если **ниже `min`** — открывает экран «Нужно обновить приложение», дальше не пускает.

1. Добавить в ответ `GET /client/app-config` поле (не трогая `modules`):

   ```json
   {
     "modules": { ... },
     "appVersions": {
       "ios":     {"latest": "1.2.6", "min": null},
       "android": {"latest": "1.2.6", "min": null}
     }
   }
   ```

   Строки вида `1.2.6`; `null` или пустая строка — проверки нет. Старые версии приложения поле
   игнорируют.
2. Хранить значения в настройках приложения (там же, где видимость разделов) и отдавать их
   **и без входа**, если `app-config` доступен гостю (иначе — после входа, как сейчас).
3. В `platform_admin`, раздел «Приложение», — блок «Версии»: для iOS и Android по два поля,
   «Последняя в магазине» и «Минимальная (обязательное обновление)», с подсказкой: «Минимальную
   поднимать, только когда старые версии перестают работать — пользователей ниже неё приложение
   не пустит дальше экрана обновления». Изменения — в журнал админки.
4. Начальные значения: `latest` = `1.2.6` для обеих платформ **после того, как 1.2.6 появится в
   магазинах**; `min` — пусто.

**Проверка:** выставить `android.latest = 9.9.9` → в приложении 1.2.6 после перезапуска (или
возврата в приложение) видна плашка; вернуть `1.2.6` — плашки нет. `min = 9.9.9` → экран
обновления; очистить `min` → приложение открывается.

# 24.11.2026 — срочно: поправка к задаче 8 (общие места ломают приложение 1.2.5)

> **Статус: не начато. Срочно — затрагивает всех медпредов на 1.2.5.**

После задачи 8 (общие места) `myRank` стал «спортивным» местом (у всех с 0 чеков — 14). Приложение
**1.2.5** использует `myRank` как **позицию строки в списке**: показывает строки до «вашей + 2»
и подсказку «до {myRank − 1} места». Итог на проде (скриншоты 24.11): список обрывается на 16-й
строке, остальные медпреды с 0 (в т. ч. Мафтуна Бахрамова, id 144) не видны, своя строка
медпреда не подсвечена, подсказка «13-o'ringacha yana 1 ta chek» (на деле место выше — 12).

**Решение владельца (24.11.2026): два отдельных топа — по чекам и по бланкам.** Медпред с нулём
в топе — «без места» в этом топе (например, у Мафтуны 0 чеков → без места в топе по чекам; 58
одобренных бланков → своё место в топе по бланкам). Топы по фармацевтам, врачам и квестам
приложение 1.2.6+ больше не показывает, но старые версии их запрашивают — эндпоинты не убирать.

**Сделать в `GET /client/medrep/leaderboard` (для всех метрик):**

1. В `items` — **только медпреды компании со значением > 0** (и только активные: отключённые в
   админке, как «Вольга Калинин», не показывать).
2. Если у медпреда значение 0 — его строки в `items` нет и **`myRank = 0`**. Тогда и 1.2.5, и
   1.2.6 показывают «Вас пока нет в рейтинге» и топ-5.
3. `items[].rank` — общее место при равенстве (1, 2, 2, 4), как сейчас.
4. Если у медпреда значение > 0 — `myRank` = **позиция его строки в `items`** (1-based, подряд),
   а не общее место: 1.2.5 режет список по `myRank` (показывает строки до «вашей + 2»), 1.2.6
   берёт место из строки `isMe`.
5. Строка `isMe: true` — с настоящим именем (задача 8).

**Проверка:** Мафтуна Бахрамова (id 144): `metric=checks` — её нет в `items`, `myRank = 0`;
`metric=recipes` — её строка с 58, `myRank` = номер строки. Медпред с чеками и общим местом
(например, 10 и 10) — `myRank` = номер строки, в 1.2.5 его строка видна и подсвечена.

## Задача 10. Ключ закрытого видео в `videoUrl`

**Жалоба (скриншот 25.11):** курс «Доритрицин» (шаблон 14, копия в боте — курс 31), видеоурок

`private_hash = f468bbcba0`. Без ключа Vimeo такое видео не показывает. Закрытых видео в
библиотеке — 9 (`private_hash` не пустой).

**Сделать:**

   причина той же ошибки: либо разрешить встраивание везде, либо добавить домены
   `pharmview.uz` и `player.vimeo.com`. Проверить настройки этих 9 видео.
