Когда пункт сделан в коде — перенести его в раздел «Готово в ветке». Перед сборкой этот раздел
становится списком изменений релиза.

## Готово в ветке `release/1.2-redesign` (после 1.2.1)

Сделано 26.10.2026, закоммичено 09.11.2026:

  показывает «Этот Telegram ещё не зарегистрирован» и открывает регистрацию. Раньше — тост

- **Пуш «Ваучер выдан»** открывает сам ваучер с QR (`/app/wallet/voucher/{id}`), а не кошелёк.

## Нужно сделать

Найдено при обходе веб-версии 26.10.2026 (тест-аккаунт Тимур, роли фармацевт, врач, медпред).

### Поведение

0. **ВАЖНО — приложение выкидывает на вход при любой ошибке связи.** `auth_controller.dart::build`
   при запуске вызывает `/auth/userCheck` и в `catch (_)` чистит токен (`tokens.clear()`) — на ЛЮБУЮ
   ошибку: нет интернета, слабая связь, таймаут, сервер перезапускается при выкатке (~10 с, бывает
   несколько раз в день). Чистить токен только при `ApiException.unauthorized` (401); при сетевой
   ошибке оставаться залогиненным (последний аккаунт из кэша или повтор запроса). Жалоба 04.11.2026:
   «вылетает раз в день-два». Серверная часть уже сделана 04.11: срок входа 180 дней, и он считается
   от выдачи токена по текущей настройке — продлил и все выданные ранее токены.
   Желательно и продление: если токену больше 30 дней, получить новый (эндпоинт можно добавить на
   сервере, `/auth/userCheck` может отдавать свежий `token`) — тогда активные люди не выйдут никогда.

0a. **ВАЖНО — чеки «на ожидании отправки» при нормальной связи.** Жалоба 09.11.2026, фармацевт
   Баратова Ойдин (+998700290164, Android): из приложения с 31.10 не дошёл ни один чек. В nginx —
   десятки `POST /client/checks` с ответом 400 и пустым телом (телефон оборвал загрузку) и 413
   (больше 20 МБ). Причины и что сделать:
   - **Фото без сжатия.** `upload_sheet.dart` и `recipe_camera_screen.dart` вызывают
     `pickImage/pickMultiImage` без `imageQuality`/`maxWidth` — уходит исходник камеры 5–25 МБ.
     Поставить `imageQuality: 80, maxWidth: 2000, maxHeight: 2000` — чек ~0,5 МБ, OCR хватает.
   - **Очередь встаёт на первом отказе.** `upload_queue.dart::_process` делает `break` на любой
     ошибке, и следующие чеки ждут вечно; повтор — только при запуске или смене сети. Нужно:
     постоянные отказы (4xx кроме 401/408/429) помечать «не отправится» с кнопками «Удалить» /
     «Переснять» и идти дальше; повторять при возврате в приложение и по таймеру; для загрузки
     отдельный `sendTimeout` побольше (сейчас общий 90 с).
   - **Android выгружает приложение, пока открыта камера** — после снимка оно стартует заново,
     фото теряется («сфоткаю — захожу заново»). Вызывать `ImagePicker().retrieveLostData()` при
     запуске и класть найденное фото в очередь. Сжатие из первого пункта уменьшает и эти вылеты.
   - **Все фото одного чека/бланка уходят одним запросом** — лимит считается на сумму. У чека до 3 фото,
     а в `recipe_camera_screen.dart` выбор из галереи (`pickMultiImage()`) без ограничения числа —
     ограничить (например, `limit: 5`).
   - **iPhone: очередь навсегда встаёт после обновления приложения.** `upload_storage_io.dart::persist`
     пишет в `queue.json` АБСОЛЮТНЫЙ путь (`…/Documents/uploads/<id>_0.jpg`), а iOS меняет путь
     контейнера приложения при обновлении/переустановке. Чек, ждавший в очереди во время
     обновления, после него «не находит» файл → `readFiles`/`MultipartFile.fromFile` падает ДО
     запроса → `break` → все новые чеки стоят за ним вечно, на сервер не приходит ни одной попытки.
     Случай 09.11: Тимур (+998909539988) — последняя загрузка из приложения 18.07. Хранить в
     очереди только имя файла и собирать путь от текущего `getApplicationDocumentsDirectory()`;
     элемент с пропавшими файлами убирать из очереди с сообщением «Фото не сохранилось — переснимите».
     Кнопка «Удалить» у застрявшего чека в UI тоже нужна (сейчас есть только «Повторить»).
     Обход до релиза — удалить приложение и установить заново (очередь лежит в его папке).
   Сервер 09.11: лимит nginx для `/api/1.0/` поднят 20 → 100 МБ (413 больше не будет), остальное — только релизом.

0b. **Каждое фото — отдельный чек (сервер, 09.11.2026).** `POST /client/checks` теперь создаёт по
   чеку на каждое фото пакета (админке так удобнее проверять; раньше 3 фото = 1 чек). В приложении
   поправить смысл экрана отправки: не «до 3 фото одного чека», а «можно выбрать несколько чеков
   сразу — каждый уйдёт отдельно»; лимит `kChecksMaxPhotos = 3` можно поднять (например, до 10 —
   сервер берёт до 10 файлов). Ответ сервера — первый чек пакета, остальные видны в «Мои чеки».

0c. **Видео урока на телефоне «грузится и не играет»** (жалоба 13.11.2026). На сервере и Vimeo всё
   в порядке: все 31 видео опубликованных курсов готовы, `embed=public`, плеер отдаёт 200, версии
   240p–1080p mp4. Проблема в плеере приложения: `lib/widgets/video_frame_io.dart` создаёт
   `WebViewController()` без настроек медиа, а `video_source.dart` просит Vimeo `autoplay=1` со звуком.
   - iOS: создавать контроллер с `WebKitWebViewControllerCreationParams(allowsInlineMediaPlayback: true,
     mediaTypesRequiringUserAction: const <PlaybackMediaTypes>{})` (пакет `webview_flutter_wkwebview`);
   - Android: `(controller.platform as AndroidWebViewController).setMediaPlaybackRequiresUserGesture(false)`
     (пакет `webview_flutter_android`);
   - в ссылку Vimeo добавить `&playsinline=1` (и при желании `&muted=1` для автозапуска без звука —
     тогда нужна подсказка «включите звук»);
   - проверить на реальных iPhone и Android до отправки в сторы.

1. **Вкладка «Квесты» не соблюдает ручной порядок из админки.**
   `quests_screen.dart:59` пересортировывает список по прогрессу
   (`sort((a, b) => b.progress.compareTo(a.progress))`), а сервер уже отдаёт квесты в нужном
   порядке: ручной из админки → иначе свежие сверху. Убрать сортировку и подпись
   «Сначала — ближе всего к награде» (`questsSortHint`). На главной порядок уже верный.

2. **Одобренный бланк навсегда «Скоро начисление».** `recipeCreditsProvider` в
   `rx_common.dart` всегда пустой (сервер не отдаёт сумму за бланк), поэтому одобренный бланк
   показывается с подписью `rxSoon` / `rxSoonCaption`. За бланк IQC отдельно не начисляются —
   он засчитывается в квест. Заменить на «Одобрен» / «Засчитан в квест»: `recipes_screen.dart:177`,
   `home_screen.dart:471` (врач), `recipe_detail_screen.dart:568`.

3. **«Нужно переснять» у фармацевта собирает все отклонённые чеки за всё время.** У тест-аккаунта
   там 9 чеков, самые старые — декабрь 2025. Туда же попадают чеки с причиной «это не чек»
   («Bu chek emas»), переснимать которые бессмысленно. Предложение: показывать отклонённые
   за последние 30 дней, остальные — только в общей истории.

4. **Совет «Сделайте чёткое фото — баллы ещё можно получить»** на экране отклонённого чека
   показывается при любой причине, в том числе «это не чек». Показывать его только для причин
   про качество фото — или убрать вторую фразу.

5. **Приветствие обращается по фамилии.** ФИО в аккаунтах записано как «Фамилия Имя», а
   приложение берёт первое слово: «Здравствуйте, Дауров» на выборе роли, «Привет, Дауров!» на
   главной врача. У фармацевта и медпреда — «Привет, Дауров Тимур!». Сделать единообразно.
   Надёжнее — отдельное поле `firstName` от сервера; его можно добавить заранее.

9. **Кошелёк не обновляется сам — выданный ваучер «не приходит».** Случай 29.10.2026: врачу
   Арзикулову (Telegram 45982450) выдали ваучер в 13:51, а в 16:11 у него в кошельке его не было,
   и в «Ждут выдачи» всё ещё стояли 2 заявки вместо 1 — данные загружены до выдачи. Провайдеры
   кошелька (`walletProvider`, `pendingAccrualsProvider`, `myVouchersProvider`,
   `walletTxnsProvider`) обновляются только при pull-to-refresh. Нужно сбрасывать их: при открытии
   «Кошелька», при возвращении приложения из фона (`AppLifecycleState.resumed`) и при получении
   пуша `type: voucher` (`push_service.dart`).

10. **Регистрация с уже существующим номером — человек жмёт «Зарегистрироваться» по кругу.** Сервер
    отвечает 409 «Аккаунт с этим номером уже существует — войдите» (108 раз за конец октября — ноябрь,
    у некоторых до 9 попыток подряд). Регистрация номер кодом не проверяет, поэтому впускать по ней
    нельзя — приложение на 409 должно сразу переводить на вход по этому номеру
    (`/login?phone=…` или сразу отправить SMS), а не показывать ошибку на форме.

## Сделано без релиза (для справки)

Эти правки уже работают у всех — на сервере, в админке и в данных. В релиз их включать не нужно.

- Ручной порядок квестов в приложении (Админка → Квесты → «Порядок в приложении»).
- Выдача ваучеров в приложение: канал «Только в приложение», запасной путь, если Telegram не
  доставил, поиск получателя по телефону и имени, пуш «Ваучер выдан».
- «Показать QR» из уведомления открывает экран ваучера (сервер отдаёт полноэкранную ссылку,
  работает и в 1.2.0).
- Вход через Telegram больше не создаёт аккаунт незнакомому человеку.
- Категории курсов: английская «General» заменена на категории из шаблонов.
- Видео урока «Тонзилгон Н» играет в приложении (настройки Vimeo).
- Исключения в таргетинге курсов и квестов: «кроме этих сетей / людей» (02.11.2026) — в
  приложении работает само (сервер не отдаёт исключённым курс или квест).
- **Вход в приложении — 180 дней** вместо 7, срок считается от выдачи токена — продлились и уже
  выданные (04.11.2026). Сменён секрет подписи токенов (был стандартный из примера) — все вошли
  заново один раз. Для релиза важно: токен по-прежнему не продлевается сам — см. пункт 0.
- Лимит загрузки на сервере 20 → 100 МБ на запрос (09.11.2026): несжатые фото чеков больше не
  получают 413. Сжатие в приложении всё равно нужно — пункт 0a.
- **Каждое фото из одной отправки — отдельный чек** (09.11.2026) — см. пункт 0b про тексты.
- Участник открывает свой завершённый (выключенный в админке) квест — раньше «Квест не найден» (09.11.2026).
- Сводка «Рецептов» в админке и весь API больше не тормозят из-за пересчёта подозрительных
  рецептов (09.11.2026) — на приложение влияло: в эти минуты могли подвисать запросы.

- Курсы на двух языках: отдельная обложка и отдельное видео урока для узбекского (13.11.2026) —
  приложение получает нужную обложку и видео от сервера по языку ученика, правок в нём не требуется.

## Подготовка релиза — чек-лист

1. Сделать пункты из «Нужно сделать», прогнать `flutter analyze` и `flutter test`.
2. Поднять версию в `pubspec.yaml` (последняя в сторах — `1.2.1+4`, следующая — `1.2.2+5`).
3. После правок моделей — `dart run build_runner build --delete-conflicting-outputs`;
   после правок `.arb` — `flutter gen-l10n` (сгенерированные файлы форматировать `dart format lib/l10n/gen`).
4. Сборки: iOS — архив и загрузка в App Store Connect, Android — `flutter build appbundle`
   (подробности — `BUILD.md`, отчёт прошлого релиза — `docs/store/release-1.2.1-status.md`).
5. Тексты «Что нового» — по разделу «Готово в ветке» этого файла.
6. Веб-версию обновить на сервере: `./deploy_web.sh`.
