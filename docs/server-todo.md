# Что нужно сделать на сервере

Приложение (ветка `release/1.2-redesign`) уже умеет всё, что ниже. Пока сервер этого не отдаёт,
приложение не ломается — просто показывает меньше. Список от самого важного.

Базовый адрес: `https://pharmview.uz/api/1.0`. Контракт команды и кодового слова —
в [medrep-team-api.md](medrep-team-api.md).

## 1. Статус «Доп. проверка» у чеков и бланков

**Что нужно.** Когда чек или бланк уходит на дополнительную (ручную) проверку, отдавать в поле
`status` значение **`review`**:

- `GET /client/checks`, `GET /client/checks/{id}`
- `GET /client/recipes`, `GET /client/recipes/{id}`
- `recentChecks[].status` в `GET /client/medrep/pharmacists/{telegramId}`

**Что сейчас.** Приложение знает статусы `pending`, `ai_detected`, `ai_wrong`, `approved`,
`rejected`. Они работают как раньше: `ai_wrong` у чека — «На проверке», у бланка — «Отклонён».

**Что увидит пользователь.** Фиолетовый статус «Доп. проверка», шаг прогресса «Доп. проверка» и
блок «Ничего делать не нужно». Пока сервер шлёт другое значение, такой чек выглядит как
«На проверке».

**Если значение будет называться иначе** — сообщите название, в приложении это одна строка
(`lib/core/models/check.dart`, `@JsonValue('review')`).

**Желательно.** Уведомление пользователю, когда по чеку или бланку на доп. проверке принято
решение: в тексте экрана обещано «Решение придёт в уведомлениях».

## 2. Карточка врача в команде медпреда

**Что нужно.** Запрос по одному врачу, например `GET /client/medrep/doctors/{accountId}`:

```json
{
  "accountId": 2879, "name": "Нодира Юсупова", "specialty": "Терапевт",
  "workplace": "Поликлиника №10", "city": "Ташкент",
  "recipes": 34, "approvedPacks": 52, "quests": 1,
  "active": true, "joinedAt": "2026-08-12T10:00:00+00:00",
  "recentRecipes": [
    {"id": 5, "createdAt": "2026-10-07T11:20:00+00:00", "status": "review"},
    {"id": 4, "createdAt": "2026-06-30T18:38:00+00:00", "status": "approved"},
    {"id": 3, "createdAt": "2026-06-20T16:05:00+00:00", "status": "rejected"}
  ]
}
```

Данные пациентов и фото бланков медпреду не отдавать — на экране прямо написано
«Данные пациентов медпреду не показываются».

**Что сейчас.** Запроса нет (`/client/medrep/doctors/{id}` отвечает 404). Карточка строится из
строки `GET /client/medrep/team`: вместо «упаковок» и «квестов» показаны `approved` и `lastAt`,
списка «Последние бланки» нет.

## 3. Карточка фармацевта, пришедшего из приложения

**Что нужно.** Открывать карточку фармацевта и его чеки не только по Telegram-id. Например,
принимать `accountId` в `GET /client/medrep/pharmacists/{id}` и
`POST /client/medrep/pharmacists/{id}/incentivize`, либо всегда отдавать в команде идентификатор,
по которому карточка открывается.

**Что сейчас.** В `GET /client/medrep/team` у фармацевта, который зарегистрировался в приложении
по кодовому слову, `telegramId` может быть `null`. Такой человек виден в «Команде», но его
карточка не открывается и поощрить его нельзя.

## 4. Город в заявках «Ожидают подтверждения»

**Что нужно.** Поле `city` в `GET /client/medrep/referrals/pending` — в макете под именем стоит
«SHIFO PLUS №3 · Ташкент».

**Что сейчас.** Приходит только `shop` — приложение показывает аптеку без города.

## 5. Подпись приза-ваучера в «Сапёре»

**Что нужно.** В подписях призов (`legend[].label`, призы итогов и победителей) писать ваучер без
валюты: **«ваучер 13 000»**.

**Что сейчас.** Приложение само отрезает «сум», «so‘m», «UZS» и «IQC» в конце подписи ваучера,
так что в приложении уже правильно. Правка на сервере нужна, чтобы подпись была одинаковой в
боте, на сайте и в уведомлениях.

## 6. Тексты уведомлений медпреду

Ссылки-приглашения в приложении нет — только кодовое слово (см.
[RELEASE_DECISIONS.md](RELEASE_DECISIONS.md)). В уведомлениях и письмах, которые видит
пользователь приложения, не стоит упоминать «ссылку-приглашение» как способ попасть в команду
через приложение. Поле `inviteLink` в `GET /client/medrep/code` приложение не использует —
его можно оставить для бота.

## Проверено на сервере 08.10.2026

- `GET /reference/registration-schema?role=doctor|pharmacist` отдаёт поле `medrepCode`
  (`maxLength: 6`, у врача `required: true`).
- `POST /auth/medrep-code/check` отвечает `{"ok": false}` на несуществующее слово.
- `GET /client/medrep/team`, `/client/medrep/code`, `/client/medrep/referrals/pending`
  существуют (без входа — 401). Ответы с данными я не видел: нет доступа под медпредом,
  приложение написано по контракту из medrep-team-api.md.
