# Что сервер отдаёт приложению 1.2

Все шесть пунктов из прошлой версии этого файла сделаны на сервере **08.10.2026** и работают на
проде. Ниже — фактический контракт: что приходит, где это видно в приложении и что осталось
за кадром. Базовый адрес: `https://pharmview.uz/api/1.0`. Контракт команды и кодового слова —
в [medrep-team-api.md](medrep-team-api.md).

## 1. Статус «Доп. проверка» — готово

В поле `status` приходит значение **`review`**:

- `GET /client/checks`, `GET /client/checks/{id}`
- `GET /client/recipes`, `GET /client/recipes/{id}`
- `recentChecks[].status` в `GET /client/medrep/pharmacists/{id}`

Рядом остались поля, на которые опирается веб-версия (её можно не трогать):
`review: true`, `reviewNeedsPhoto` (модератор просит переснять фото) и `reviewSince` (ISO-время,
с которого чек на проверке). Приложение берёт `status`, остальное может игнорировать.

Важно: у **бланков** доп. проверка бывает «тихой» — модератор отложил решение, но врача не
оповещал. В этом случае наружу по-прежнему идёт `pending`: в приложении незачем показывать шаг,
про который человеку не говорили. У чеков такой развилки нет.

Уведомление о решении приходит обычным порядком — через `GET /client/notifications`
(тип `check` / `recipe`).

## 2. Карточка врача — готово

`GET /client/medrep/doctors/{accountId}` (нужна роль медпреда; врач должен быть в его команде,
иначе 404):

```json
{
  "accountId": 2747, "telegramId": 676570560,
  "name": "Zarnigor Fayzullayeva", "specialty": "Врач общей практики",
  "workplace": "Jalaquduq KTMP", "city": "Андижан", "phone": "+998902535793",
  "recipes": 145, "approved": 47, "approvedPacks": 47, "quests": 1,
  "active": true,
  "joinedAt": "2026-10-08T11:18:26+00:00", "lastAt": "2026-10-06T09:15:33+00:00",
  "recentRecipes": [{"id": 2156, "createdAt": "2026-10-06T09:15:33+00:00", "status": "rejected"}]
}
```

- `approvedPacks` — упаковки из одобренных бланков, только по препаратам компании медпреда
  (та же логика, что в отчётах по врачебным квестам).
- `quests` — рецептурные квесты по препаратам компании, которые врач уже закрыл.
- `active` — действие за последние 30 дней либо свежее вступление в команду.
- `recentRecipes` — последние 5 бланков: id, дата, статус (включая `review`). Данных пациентов и
  фото бланков в ответе нет и не будет — на экране так и написано.

## 3. Карточка фармацевта из приложения — готово

`GET /client/medrep/pharmacists/{id}` и `POST /client/medrep/pharmacists/{id}/incentivize`
принимают **и Telegram-ID, и `accountId`**. В ответе всегда есть оба идентификатора:

```json
{"telegramId": null, "accountId": 2886, "name": "…", "shop": "SHIFO PLUS №3", "city": "Ташкент",
 "phone": "+998…", "checks": 0, "quests": 0, "approvedPacks": 0, "lastActivity": "", "recentChecks": []}
```

У пришедшего по кодовому слову карточка собирается из аккаунта, анкеты регистрации и чеков,
отправленных из приложения; в ботах его нет, поэтому `quests` там 0.

## 4. Город в заявках «Ожидают подтверждения» — готово

`GET /client/medrep/referrals/pending` отдаёт `city` (у заявок из бота — из справочника городов,
у заявок из приложения — из анкеты) и `shop` в обоих случаях.

## 5. Подпись приза-ваучера в «Сапёре» — готово

Сервер срезает валюту у ручных подписей призов-ваучеров: «ваучер 13 000 сум» → «ваучер 13 000»
(так же для `so'm` и `UZS`). Подписи IQC не меняются. Теперь подпись одинаковая в приложении,
боте и уведомлениях — обрезку на клиенте можно оставить как страховку.

## 6. Тексты уведомлений медпреду — готово

Уведомление о новом участнике: «присоединился к вашей команде **по кодовому слову**» или
«ввёл ваше кодовое слово и ждёт подтверждения». Про ссылку-приглашение в уведомлениях приложения
не упоминаем; поле `inviteLink` в `GET /client/medrep/code` осталось для бота.

## Что изменилось в регистрации

Анкета регистрации из приложения раньше нигде не сохранялась — оставались только телефон, ФИО и
роль, поэтому город, аптека, клиника и специальности терялись (из-за этого пункты 3 и 4 и были
пустыми). Теперь `POST /auth/register` сохраняет анкету на сервере: город и специальности
приходят id-шниками справочника, на сервере разворачиваются в названия. На клиенте менять ничего
не нужно — поля те же.

## Нужно к 1.2.2 — в какой квест засчитан бланк

Макет RxApproved показывает под одобренным бланком карточку «Засчитан в квест»: название квеста
и прогресс врача по нему. Сервер сейчас этого не отдаёт, поэтому приложение рисует вариант без
квеста (RxApprovedNoQuest): «Засчитан в квест» без названия и прогресса.

Что нужно в `GET /client/recipes/{id}` (и, по возможности, в `GET /client/recipes`) для
одобренного бланка:

```json
"countedIn": {
  "questId": 12, "title": "Доритрицин — осень",
  "got": 6, "need": 10, "unit": "уп."
}
```

- `countedIn` = `null`, если бланк не попал ни в один активный квест врача.
- Если бланк засчитан в несколько квестов — массив `countedIn: [...]`, приложение покажет первый.
- Нынешние версии приложения новое поле просто проигнорируют; показывать квест начнём в
  следующей версии после того, как поле появится.
