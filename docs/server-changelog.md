# Что изменено на сервере для приложения 1.2

Короткая запись для локальной машины: что именно поменялось на проде, чтобы не искать в чате.
Сервер — `platform_api` (образ, выкатка `docker compose up -d --build --force-recreate platform_api`),
база — `telegram_bot_db`. Контракты для клиента описаны в [server-todo.md](server-todo.md) и
[medrep-team-api.md](medrep-team-api.md); здесь — только изменения на стороне сервера.

## 08.10.2026 — шесть пунктов из server-todo

**Миграция 015** (`platform_api/migrations/015_account_profile.up.sql`, применена):

- `platform.account_profile(account_id, role, city, shop, workplace, specialty, values, …)` —
  анкета регистрации из приложения. До этого `POST /auth/register` сохранял только телефон, ФИО
  и роль, поэтому город, аптека, клиника и специальности терялись.
- `platform.incentive.account_id` — поощрение фармацевта, у которого нет Telegram.

**Эндпоинты и логика:**

| Где | Что сделано |
|---|---|
| `routers/client.py` | `_with_review()` — чек/бланк на доп. проверке отдаётся как `status: "review"` в списках и карточках. Флаги `review/reviewNeedsPhoto/reviewSince` сохранены для веб-версии. «Тихая» доп. проверка бланка (без оповещения врача) наружу не показывается. |
| `routers/medrep.py` | Новый `GET /client/medrep/doctors/{accountId}` (карточка врача: упаковки, квесты, последние 5 бланков, без данных пациентов). `_resolve_pharmacist()` — карточка и поощрение фармацевта по Telegram-ID **или** `accountId`, `_app_pharmacist_card()` для пришедших из приложения. `city`/`shop` в `/referrals/pending` и в фармацевтах `/team`. `recentChecks[].status` → `review`. |
| `routers/auth.py` | `_save_profile()` — анкета регистрации пишется в `platform.account_profile`; id города и специальностей разворачиваются в названия по справочникам. |
| `minesweeper.py` | `prize_label()` срезает валюту у ручных подписей призов-ваучеров («ваучер 13 000 сум» → «ваучер 13 000»); IQC не трогает. |
| `medrep_code.py` | Текст уведомления медпреду: «по кодовому слову» / «ввёл ваше кодовое слово и ждёт подтверждения», без упоминания ссылки-приглашения. |

**Проверено запросами на проде:** `review` появляется и исчезает при постановке/снятии доп.
проверки (чек и бланк, включая «тихий» режим), карточка врача и фармацевта (по Telegram-ID и по
`accountId`), поощрение по `accountId`, город и аптека в заявках, сохранение анкеты при
регистрации. Тестовые аккаунты и записи команды после проверок удалены.

## Что на сервере НЕ сделано

- Отдельного уведомления «решение по доп. проверке принято» нет — приходит обычное уведомление о
  статусе чека/бланка.
- У фармацевта из приложения `quests` всегда 0: квесты живут в ботах, а его в ботах нет.
- Ссылка-приглашение осталась в формате бота (`?start=ref_<telegram_id>`) — в приложении
  используется только кодовое слово.
