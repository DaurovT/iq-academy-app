# Что изменено на сервере для приложения 1.2

Короткая запись для локальной машины: что именно поменялось на проде, чтобы не искать в чате.
Сервер — `platform_api` (образ, выкатка `docker compose up -d --build --force-recreate platform_api`),
база — `telegram_bot_db`. Контракты для клиента описаны в [server-todo.md](server-todo.md) и
[medrep-team-api.md](medrep-team-api.md); здесь — только изменения на стороне сервера.

## 08.10.2026 — шесть пунктов из server-todo

**Миграция 015** (`platform_api/migrations/015_account_profile.up.sql`, применена):

- `platform.account_profile(account_id, role, city, shop, workplace, specialty, values, …)` —
  анкета регистрации из приложения. До этого `POST /auth/register` сохранял только телефон, ФИО
  и роль, поэтому город, аптека, клиника и специальности терялись.
- `platform.incentive.account_id` — поощрение фармацевта, у которого нет Telegram.

**Эндпоинты и логика:**

| Где | Что сделано |
|---|---|
| `routers/client.py` | `_with_review()` — чек/бланк на доп. проверке отдаётся как `status: "review"` в списках и карточках. Флаги `review/reviewNeedsPhoto/reviewSince` сохранены для веб-версии. «Тихая» доп. проверка бланка (без оповещения врача) наружу не показывается. |
| `routers/medrep.py` | Новый `GET /client/medrep/doctors/{accountId}` (карточка врача: упаковки, квесты, последние 5 бланков, без данных пациентов). `_resolve_pharmacist()` — карточка и поощрение фармацевта по Telegram-ID **или** `accountId`, `_app_pharmacist_card()` для пришедших из приложения. `city`/`shop` в `/referrals/pending` и в фармацевтах `/team`. `recentChecks[].status` → `review`. |
| `routers/auth.py` | `_save_profile()` — анкета регистрации пишется в `platform.account_profile`; id города и специальностей разворачиваются в названия по справочникам. |
| `minesweeper.py` | `prize_label()` срезает валюту у ручных подписей призов-ваучеров («ваучер 13 000 сум» → «ваучер 13 000»); IQC не трогает. |
| `medrep_code.py` | Текст уведомления медпреду: «по кодовому слову» / «ввёл ваше кодовое слово и ждёт подтверждения», без упоминания ссылки-приглашения. |

**Проверено запросами на проде:** `review` появляется и исчезает при постановке/снятии доп.
проверки (чек и бланк, включая «тихий» режим), карточка врача и фармацевта (по Telegram-ID и по
`accountId`), поощрение по `accountId`, город и аптека в заявках, сохранение анкеты при
регистрации. Тестовые аккаунты и записи команды после проверок удалены.

## Что на сервере НЕ сделано

- Отдельного уведомления «решение по доп. проверке принято» нет — приходит обычное уведомление о
  статусе чека/бланка.
- У фармацевта из приложения `quests` всегда 0: квесты живут в ботах, а его в ботах нет.
- Ссылка-приглашение осталась в формате бота (`?start=ref_<telegram_id>`) — в приложении
  используется только кодовое слово.

## 19.11.2026 — задачи из SERVER_TASKS.md (медпреды: бланки врачей, заявки из приложения)

Миграций нет. Резервные копии — `/root/backups/*.bak-2026-11-19`, таблицы —
`/root/backups/medrep-tables-2026-11-19.sql`.

| Где | Что сделано |
|---|---|
| `medrep_stats.py` (новый) | `recipe_stats()` / `recipe_board()` — бланки врачей команды, считаются на лету. Врачей ищем через `platform.account_telegram_links`: в `team_member.telegram_id` у всех пусто. `shared_metrics()` + `refresh_cache()` — показатели по чекам всех медпредов одним запросом (0,3 с; формулы те же, что `medpred_metrics.py` в боте, сверено с кэшем: 138 из 139 совпали, расхождение — привязка того же дня). `refresh_loop()` — пересчёт `medpred_metrics_cache` раз в 15 минут и сразу после принятия заявки. |
| `routers/medrep.py` | `GET /metrics`: всегда отдаёт `recipesCount`, `approvedRecipes`, `recipePacksSum` (+ `doctorsCount`); `questsDone` — плюс рецептурные квесты врачей; **`from`/`to` теперь работают** и для чеков (раньше период игнорировался — «7 дней» и «30 дней» показывали «за всё время»). `GET /leaderboard`: `metric=recipes` (одобренные бланки) и `metric=doctors`; в них только медпреды компании, у которых есть врачи. `GET /team`: у врачей `recipes`/`approved` были нулями (сравнение с пустым `telegram_id`) — исправлено. Принятие заявки из приложения — через `medrep_code.accept_pending()`. |
| `medrep_code.py` | `accept_pending()` / `reject_pending()` / `link_pharmacist()`. Принятый фармацевт записывается ещё и в `public.pharm_user_medreps` (source `manual_code`): по этой таблице считаются показатели и рейтинг, без записи его чеки не засчитывались никому. Правило «один медпред в компании» соблюдается: 409, перевод — только из админки. |
| `routers/admin.py` | `GET /admin/medreps/{mid}/pending` — заявки из бота и из приложения: `id`, `kind`, `accountId`, `name`, `phone`, `shop`, `city`, `source`, `requestedAt` (старые `tgUserId`/`capturedAt` сохранены). `pendingCount`, `/medreps-summary`, фильтр «Ждут привязки» считают оба вида. `POST …/pending/accept|reject` принимают `{kind: "app", accountId}` (для бота — как раньше `{tgUserId}`), перевод — `transfer: true`. `GET /admin/users/{tid}` — `pendingMedreps[]` («ждёт подтверждения: медпред, с какого времени»). `/admin/medreps` и `/admin/medreps/{mid}` — `doctorsCount`, `recipesCount`, `approvedRecipes`. Ручная привязка `POST /admin/users/{tid}/medreps` закрывает ждущую заявку к этому медпреду. |
| `platform_admin` | Карточка медпреда: заявки из приложения с пометкой «из приложения», телефоном, аптекой и городом; плитки «Врачи» и «Бланки». В списке — «N врачей · M бл.». В карточке пользователя — «Ждёт подтверждения: …». |

**Данные (разово):** 24 фармацевта, уже принятых по кодовому слову, дописаны в
`pharm_user_medreps` (у них было 44 одобренных чека вне статистики); один (аккаунт 2903) без
профиля фармацевта остался только в `team_member`. Две заявки к медпреду 144, привязанные вручную
19.11, помечены принятыми.

**Проверено на проде:** метрики и оба новых рейтинга у медпредов 73 и 144; заявка демо-фармацевта
(`+998 90 111 22 33`) видна в `/admin/medreps/{mid}/pending`, в счётчиках и в карточке
пользователя, отклоняется и принимается из админки, после принятия он в команде. Тестовые записи
удалены.

  кэш, как раньше, ведёт бот раз в сутки.
- 15 заявок из приложения, висевших у пяти медпредов (92, 93, 127, 129, 141), приняты с сервера
  19.11.2026 по решению владельца — конфликтов не было, ждущих заявок не осталось.
